Trade Terminal

2026
  • Quantitative Finance
  • C++
  • ImGui
  • OpenGL

A Bloomberg terminal is a cool program, but sadly I am in no position to afford the yearly fee. Interactive Brokers does come with its own GUI but sometimes I just need some tweaks and maybe different kinds of information. So, this seemed like the best time to sharpen my C++ skills and use OpenGL and ImGui to build an application that satisfies all my needs.

After having watched “The Cherno”s video on how to build applications using ImGui, it was clear that this library is the best solution. Working with it is extremely straightforward and every design decision can be read in the source code. This is something I find extremely enjoyable in C or C++ compared to Python, that there is very little abstraction and you download the whole source code and can read what the developers did and why they did it.

The first version of the terminal is just an overview of open positions, transactions, an equity curve, and a window that allows me to run my strategy. Currently the strategy is still written in Python, as all needed mathematical libraries are there and ready to use. The strategy is then executed with an easy system call and the output is written to a database that can then be read by the terminal. This way I can keep a good historical overview of all my transactions.

Next Steps

In the future I will adopt some changes. For one, I will rewrite the current terminal rendering logic to make it more structured with proper namespaces. As my strategy is currently focused on the NYSE, I will also implement a digital clock at the bottom that lets me know the current time of all key locations. On top of this I want to optimise the strategy by using different news APIs and if a potential entry is found, the ticker should be clickable to read current news on the stock to see what is going on. Obviously if I develop other strategies they should also be callable from the terminal, and ideally build themselves in C++.
